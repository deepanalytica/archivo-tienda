RUST · deep-mining-trust-core · v0.2

Qué construí y qué puede comprobarse

El repositorio contiene un núcleo en Rust que define evidencias, afirmaciones, pronósticos y decisiones mediante tipos y reglas explícitas. Incluye pruebas unitarias. La documentación de la arquitectura más amplia está publicada por separado.

MH-EVID-001Un hecho sin evidencia verificada vinculada produce un bloqueo.
MH-KEY-001Una decisión de alto impacto sin aprobación humana produce un bloqueo.
MH-FC-003Un pronóstico que no mejora su baseline se marca como advertencia.

Estas reglas sirven para detener incumplimientos concretos. No pueden garantizar por sí solas que una fuente sea verdadera ni evitar todos los errores de la IA. Distingo aquí lo implementado en Rust de los controles más amplios descritos en la arquitectura de Praxios.

01 / 18MVP experimental · demo pública

Conv OS

Conv OS es un prototipo para seguir una consulta desde que llega hasta que alguien la resuelve, con estados y responsables visibles.

PROBLEMA

Las consultas de clientes llegan por distintos canales y se mezclan con tareas, pagos y pendientes. Después cuesta reconstruir qué pasó.

PARA QUÉ SIRVE

El objetivo es que cualquier persona del equipo pueda revisar el estado de una solicitud y saber qué falta hacer.

Cómo se planteó y qué decisión se tomó +
CONSTRUCCIÓN / ARQUITECTURA

Separé la lógica de estados de la interfaz: API con Node.js, SQLite de laboratorio y reglas para cambiar el estado de los pedidos. Incorporé recepción de eventos con firma HMAC y una demo con datos ficticios.

DECISIÓN DE CRITERIO

El estado de un pedido no puede cambiar solo porque alguien escribió una frase. Las transiciones deben cumplir reglas, y la demo no se presenta como una operación con clientes reales.

02 / 18Arquitectura y código de producto

MSJ

MSJ organiza una arquitectura para recibir y coordinar conversaciones de distintos canales, con espacio para atención humana y asistencia de IA.

PROBLEMA

Un comercio y un servicio profesional pueden recibir mensajes parecidos, pero necesitan procesos, permisos y derivaciones muy diferentes.

PARA QUÉ SIRVE

La arquitectura permite pensar la atención multicanal sin rehacer todo el sistema para cada negocio. Aún requiere validación operativa.

Cómo se planteó y qué decisión se tomó +
CONSTRUCCIÓN / ARQUITECTURA

La arquitectura separa la entrada de eventos de Meta, el motor de conversación y las herramientas del negocio. Incluye estados para atender con IA, derivar a una persona o pausar el flujo.

DECISIÓN DE CRITERIO

Decidí mantener el motor independiente del rubro. Cada negocio incorpora sus propias herramientas y permisos mediante conectores, sin alterar la base de conversaciones.

05 / 18Arquitectura documentada · demostración pública

Praxios OS

Praxios organiza el trabajo entre agentes de IA a partir de tareas, evidencias, estados y autorizaciones que se pueden revisar.

PROBLEMA

Cuando varios agentes participan en una tarea, una conversación larga no permite saber con claridad quién tomó cada decisión.

PARA QUÉ SIRVE

La meta es que un equipo pueda inspeccionar el progreso, revisar pruebas y decidir cuándo autorizar un siguiente paso.

Cómo se planteó y qué decisión se tomó +
CONSTRUCCIÓN / ARQUITECTURA

La arquitectura registra metas, tareas, evidencias, propuestas y autorizaciones. El trabajo se organiza en etapas: proponer, verificar, autorizar, ejecutar y observar.

DECISIÓN DE CRITERIO

Separé la propuesta del permiso para actuar. Que un agente sugiera una acción no significa que pueda ejecutarla.

06 / 18Núcleo y reglas documentados · cobertura en evolución

Meta Harness

Meta Harness es una arquitectura de control para revisar qué afirma un agente, en qué fuentes se apoya y qué acciones está autorizado a realizar.

PROBLEMA

Un modelo puede redactar una explicación muy convincente y estar equivocado. El problema se agrava si otro agente utiliza esa respuesta como un hecho.

PARA QUÉ SIRVE

Busco detectar afirmaciones sin respaldo y decisiones que requieren revisión. Ninguna de estas reglas garantiza eliminar todos los errores.

Cómo se planteó y qué decisión se tomó +
CONSTRUCCIÓN / ARQUITECTURA

La arquitectura contempla comprobar el tipo de afirmación, su fuente, la evidencia, las contradicciones y la incertidumbre. También define cuándo interviene una revisión independiente o una autorización humana.

DECISIÓN DE CRITERIO

La comprobación no debe depender únicamente del agente que produjo la respuesta. Si una afirmación queda bloqueada, no puede alimentar una acción automática como si fuera un dato confirmado.
